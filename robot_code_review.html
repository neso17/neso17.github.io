Vision.py
CRASH
Variable shadowing crash in alignToTarget()
You pass in target as a parameter, then immediately re-assign target = None inside the loop. Then you do if m.id == target.id — but target is now None, so target.id throws AttributeError on the very first iteration.
CRASH
Circular import — Vision.py imports from robot.py
from robot import moveWithChecks at the top of Vision.py. But robot.py imports from Vision.py. Python will hit a circular import error and refuse to start. Move moveWithChecks to Movement.py instead.
CRASH
findTargetMarker() crashes when no acid markers visible
distances will be an empty list if no markers with IDs 100–139 are in view. Calling min([]) raises ValueError. Add a guard: if not distances: return None.
CRASH
findNextMarker360() returns a Marker object to min()
closeMarker is a list of Marker objects. min(closeMarker) will fail because Marker objects aren't comparable with <. You probably want min(closeMarker, key=lambda m: m.position.distance).
CRASH
returnToHome() — alignToTarget() called with an ID, not a Marker object
Line: alignToTarget(robot, curr_home_id) — you pass the integer ID. But alignToTarget immediately does target.id, which fails on an int. Pass the full marker object, or look it up first.
LOGIC
horDistCalculate() — units mismatch, will give wrong distance
targetMarker.position.distance is in mm. You square it, subtract CAMHEIGHT**2 (which is in metres — 0.12), then divide by 1000. You're mixing mm² and m². Either use mm throughout, or convert distance to metres first: dist_m = targetMarker.position.distance / 1000, then math.sqrt(dist_m**2 - CAMHEIGHT**2).
LOGIC
returnToHome() — homeM may be unbound
If the for m in markers loop finds no match, homeM is never assigned, and the if homeM: check below throws UnboundLocalError. Initialise it: homeM = None before the loop.
LOGIC
returnToHome() — distance threshold is in metres but check uses 150
dist = horDistCalculate(...) returns metres. Then if dist < 150 — that's 150 metres. You almost certainly mean 0.15 (150mm / 15cm).
LOGIC
STEPS_PER_DEGREE not imported in Vision.py
convertAngToSteps() uses STEPS_PER_DEGREE, but Vision.py only defines CAMHEIGHT. It doesn't import STEPS_PER_DEGREE from anywhere. It'll raise NameError at runtime.
Movement.py
CRASH
stepMotorsRotateAntiClockwise() — wrong comparison operator in while condition
The condition is originalStep1 - int(robot.arduino.command("t")) >= steps — uses >= instead of <=. This means the while loop exits immediately (since the difference starts at 0, which is not ≥ steps). The motor starts but the loop never waits. Compare with the clockwise version — it uses <=.
CRASH
stepMotor1Clockwise() — motor set to wrong direction
Power is set to +1, same as stepMotor1AntiClockwise(). It should be -1 for clockwise. The encoder check is correct (measures decreasing steps), but the motor will spin the wrong way.
LOGIC
Tight busy-loops with no sleep will starve the SR runtime
All motor step functions poll robot.arduino.command() in tight while loops with no robot.sleep(). This blocks Python and may interfere with the SR OS. Add a small robot.sleep(0.01) inside each loop.
robot.py
CRASH
mechanismOpen/Close called with wrong argument order
In robot.py, calls are mechanismOpen(servo1, servo2, robot). But in Mechanism.py the signature is def mechanismOpen(robot, servo1, servo2). The arguments are in the wrong order — servo1 gets passed as robot. Swap to mechanismOpen(robot, servo1, servo2).
LOGIC
visionMvnmtTest2() — subtracts 100 from a distance in metres
moveWithChecks(robot, dist - 100, target.id) — dist is in metres (e.g. 1.5). Subtracting 100 gives a large negative number, so the robot will try to drive backwards hundreds of metres in steps. Probably meant dist - 0.1 to stop 10cm short.
LOGIC
STEPS_PER_MM and CAMHEIGHT are redefined across files with different units
robot.py: CAMHEIGHT = 0.12 (metres). Movement.py: CAMHEIGHT = 120 (mm). If any function picks up the wrong one via import, distance calculations will be off by a factor of 1000. Define constants once in a single constants.py and import from there.
MINOR
initialise() is never called, and collecting is local
The function is defined but never invoked. Also, collecting = "acid" is a local variable that disappears when the function returns — probably intended to be returned or stored as a global.
