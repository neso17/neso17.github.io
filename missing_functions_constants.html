Constants you're missing (put these in a constants.py)
CONST
ALIGN_TOLERANCE = 2.0 — alignment dead-zone in degrees
You hardcode 2 in alignToTarget(). Make it a named constant so you can tune it in one place. In competition you may want to loosen this to 5° if the robot keeps oscillating.
CONST
APPROACH_STOP_DIST = 0.15 — how close to stop from a target (metres)
You use magic numbers like -100 and 150 as stop distances in several places. One named constant makes tuning this trivial.
CONST
SEARCH_ROTATE_STEPS — steps per search sweep increment
You use 30, 40, and 90 degrees in different search loops. Pick one and name it. If the robot overshoots markers while searching, you only change it in one place.
CONST
Marker ID ranges as named constants or sets
You repeat range(100, 140) and range(140, 180) in three different files. Define ACID_IDS = range(100, 140), BASE_IDS = range(140, 180), ARENA_IDS = range(20) once in constants.py.
CONST
MATCH_DURATION = 150 — match length in seconds
SR matches are 2.5 minutes. You'll want this for a time-based fallback: if you're running out of time, abort collection and return home. Use robot.time() against a start timestamp.
Functions you should add
VISION
getMarkerType(marker_id) — returns "acid", "base", or "arena"
You duplicate the if marker.id in range(100,140) chain in at least 3 places. One helper function cleans all of them up. Return an enum or string, and use it everywhere.
VISION
getVerticalAngle(marker) — vertical angle to marker in degrees
You use horizontal_angle but never vertical_angle. The SR API provides it. As the robot gets very close to a marker it will rise out of frame — tracking the vertical angle lets you detect and handle this before you lose it.
VISION
stopMotors(robot) — explicit full stop
You don't have a standalone "stop everything" function. Useful to call in error states, on match end, or when a marker is suddenly lost mid-approach. Just sets both motors to BRAKE.
MOVEMENT
driveToMarker(robot, target_id) — combined align + approach loop
Right now you call alignToTarget, then calculate distance, then moveWithChecks as three separate steps. A single function that wraps all three (stop when close, re-align if drifting) would be much cleaner for the main loop.
TIMING
timeRemaining(robot, start_time) — seconds left in match
Use robot.time() (which you're not using at all yet) to track elapsed time. This lets you add a "panic mode" — if less than 20 seconds remain, drop whatever you're doing and run home.
SAFETY
safeCamera(robot, retries=3) — wrapper around robot.camera.see()
Camera calls can occasionally return empty or throw. A wrapper that retries a few times with a short sleep between attempts will make your vision code much more robust in a noisy arena environment.
DEBUG
indicateError(robot) / indicateCollecting(robot) — state LEDs
You have indicatePowerOn but no other LED state functions. Having distinct LED patterns for "searching", "aligning", "approaching", "error" makes debugging on the arena floor much easier — you can see what state the robot thinks it's in without a laptop.
MISSING
No use of robot.time() anywhere
The SR API has robot.time() which gives you elapsed time. You have no timeout logic at all — if the robot gets stuck in a search loop or loses a marker, it will spin forever. Every major loop should have a timeout escape: if robot.time() - loop_start > 10: break.
MISSING
No use of robot.is_simulated
The API exposes robot.is_simulated. Useful for tweaking constants (e.g. tighter tolerances in sim where vision is perfect) or skipping hardware-specific calls. Worth at least logging it on startup.
MISSING
No use of robot.wait_start() pattern
You're using Robot() which blocks until start. The docs recommend Robot(wait_for_start=False) followed by hardware setup, then robot.wait_start(). This lets you initialise servos to their correct starting position before the match starts rather than after.
